Pointers & References

A pointer stores a memory address instead of a value. This is where C++ gives you real control — and real ways to shoot yourself in the foot, if you're not careful.

the address-of operator: &

Every variable lives somewhere in memory. & gives you that address.

address-of.cpp
int age = 25;
std::cout << "value: "   << age  << std::endl;
std::cout << "address: " << &age << std::endl;
output
value: 25
address: 0x7ffeeb1a2c3c

That address will look different every time you run the program — memory locations aren't fixed.

declaring & using a pointer

A pointer's type must match what it points to. * in a declaration marks a variable as a pointer; * in an expression dereferences it — follows the address to get the value stored there.

pointer-basic.cpp
int age = 25;
int* agePtr = &age;    // agePtr holds the address of age

std::cout << "pointer holds address: " << agePtr  << std::endl;
std::cout << "value at that address: " << *agePtr << std::endl;

*agePtr = 30;  // changes age itself, through the pointer
std::cout << "age is now: " << age << std::endl;
output
pointer holds address: 0x7ffeeb1a2c3c
value at that address: 25
age is now: 30

nullptr

A pointer that isn't pointing at anything yet should be set to nullptr, not left uninitialized. Always check before dereferencing.

nullptr.cpp
int* ptr = nullptr;

if (ptr != nullptr) {
    std::cout << *ptr << std::endl;
} else {
    std::cout << "ptr isn't pointing at anything yet." << std::endl;
}
output
ptr isn't pointing at anything yet.
common pitfall
Dereferencing a nullptr (or any invalid pointer) crashes your program at best, and silently corrupts memory at worst. This is the single most common source of C++ crashes for newcomers.

pointers and arrays

An array's name decays into a pointer to its first element — which is why pointer arithmetic can walk through an array.

pointer-array.cpp
int nums[3] = {10, 20, 30};
int* p = nums;    // points at nums[0]

std::cout << *p << std::endl;       // 10
std::cout << *(p + 1) << std::endl; // 20 — moves forward one int
std::cout << *(p + 2) << std::endl; // 30

references — a safer alternative

A reference (& in a declaration) is an alias for an existing variable. Unlike a pointer, it can't be nullptr and can't be reassigned to refer to something else — which removes two whole categories of bugs.

references.cpp
int score = 100;
int& scoreRef = score;   // scoreRef IS score, just another name for it

scoreRef += 50;
std::cout << score << std::endl;  // 150 — changing the reference changes the original
output
150
tip
In modern C++, prefer references for function parameters (see the Functions chapter) and reach for raw pointers mainly for optional values or low-level work. For owning dynamic memory, prefer smart pointers (std::unique_ptr, std::shared_ptr) over raw new/delete — a great next topic once you're comfortable here.
